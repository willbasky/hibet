# Тесты hewts

Как запускать набор, как он устроен и откуда берутся ожидания.

Запуск (из `hewts/`):

```
cabal test hewts-test
```

## Два слоя

Набор делится на два слоя по происхождению ожидания:

| Слой | Где живёт | Группа в tasty | Ожидания |
|---|---|---|---|
| **эталонный** | `test/vectors/` + `Test.Parity` | `reference vectors (parity)` | скопированы из референсов — дословно или извлечены из их кода |
| **hewts** | остальные модули `test/Test/*` | корень `hewts` | собственные проверки hewts; часть обоснована книгой или спецификацией EWTS |

Тот же ответ даёт и дерево: падение внутри `reference vectors (parity)` — это
расхождение с эталоном; любое другое — собственное свойство hewts.

## Происхождение ожиданий: индекс

Живой перечень «модуль → источник ожиданий». Он нужен, чтобы при падении было
видно, спорим мы с эталоном или проверяем своё, и чтобы наше свидетельство не
выдавалось за эталонное.

| Модуль | Источник ожиданий |
|---|---|
| `Test.Parity` + `test/vectors/` | **эталон**: копии тестов референсов (jsewts, Lingua, ewts-js, ewts-rs, java, Кангьюр) |
| `Test.Grammar.Constraint.Constraint01`, `08`–`20` | **книга** (Nyima Tashi), правило NN |
| `Test.Grammar.Structure` | **книга** (Nyima Tashi): 37 структур слога |
| `Test.Grammar.Wylie` | **книга** (структуры) + **оракулы EWTS** (совпадение с эталоном) |
| `Test.Grammar.Stack` | **оракулы EWTS** (метки jsewts) + hewts (обобщённый стек) |
| `Test.Grammar.Syllable` | **hewts**: мост AST (REFACTOR-AST шаг 1), корпуса — генератор |
| `Test.Tokenizer.Classification` | **спецификация EWTS**: таблицы букв, алиасы, раскрытия |
| `Test.Tokenizer.Tricky` | **оракулы EWTS**: правила входа (что пропускается, что сообщается); формулировки диагностик — hewts |
| `Test.Tokenizer.RoundTrip` | **hewts**: инвариант обратимости; написания — **оракулы EWTS** |
| `Test.Tokenizer.Integration` | **hewts**: рендер, raw-roundtrip, escape |
| `Test.Tokenizer.Spans` | **hewts**: непрерывность спанов |
| `Test.Tokenizer.Golden` | **hewts**: снимки токен-потока |
| `Test.Convert` | **hewts**: публичный API (`splitSentences`, `syllables`, `pSentence`) |
| `Test.Convert.Sentence` | **hewts**: уровень документа (тшег, shad, числа) |
| `Test.Convert.Golden` | **hewts**: снимки конверсии — U→W поверх `kang.txt`, W→U поверх векторов паритета |
| `Test.Diagnostic` | **hewts**: канал диагностики (коды и формулировки наши, 30.09.2026) |

Источники означают: **книга** — «Research on Tibetan Spelling Formal Language and
Automata with Application» (Nyima Tashi) в `Documents/`; **спецификация EWTS** —
стандарт THL Extended Wylie; **оракулы EWTS** — исходники конверторов в
`convertors/main/` (jsewts, Lingua, ewts-rs, ewts-converter/java). Каждый модуль
несёт ту же пометку первой строкой шапки.

## Эталонные векторы (`test/vectors/`)

Проверочные примеры, скопированные из референсов. Ничего из этого не участвует в
сборке библиотеки — файлы читает только тест-суит.

### Состав и происхождение

| Файл | Что это | Откуда | Ревизия |
|---|---|---|---|
| `jsewts_parity.tsv` | 210 случаев, W→U и U→W | `jsewts/test/test.txt` | jsewts `a3c8c6b` (2025-09-05) |
| `lingua_parity.tsv` | 218 случаев, тот же формат | `Lingua-BO-Wylie/t/test.txt` | без git-истории в нашей копии |
| `kang.txt` | 254 строки тибетского текста, без ожиданий | `jsewts/test/kang.txt` | jsewts `a3c8c6b` |
| `wkang.txt` | 254 строки Wylie — эталонный вывод U→W тех же строк | `jsewts/test/wkang.txt` (`toWylie(kang.txt)`) | jsewts `a3c8c6b` |
| `ewts_rs_rules.tsv` | 16 правил EWTS, только W→U | `ewts-rs/ewts/src/rules_test.rs` | ewts-rs `14f7b24` (2024-12-11) |
| `java_ewts.tsv` | 5 строк, строгие EWTS-пары | `ewts-converter/.../ConversionTest.java`, метод `textEwts()` | ewts-converter `c1a6d3f` (2024-07-01) |
| `ewts_js_parity.tsv` | 212 случаев, тот же формат (EWTS W→U/U→W/roundtrip) | `ewts-js/src/EwtsConverterTests.mjs` | port java-набора (2026-05-08; 212 тестов) |

Первые три файла — **дословные копии**. Векторы правил и java-пары
(`ewts_rs_rules.tsv`, `java_ewts.tsv`, `java_sloppy.tsv`) **извлечены** из
исходников референсов, потому что там данные лежат парами в коде, а не в
таблицах.

**Выгрузки текстов предупреждений больше нет.** До 30.09.2026 рядом лежали
`*_warns*.tsv` — разовый выгруз текстов предупреждений из самих эталонов, по
которым сверялись наши сообщения. Смена стратегии (диагностика, её коды и
формулировки — наши) вывела эту сверку из паритета, и файлы удалены: хранить
чужие тексты ради проверки, которой нет, незачем. Колонки `warns` в самих
корпусах остались — по ним в Волне 6 разойдутся режимы.

### Формат

Формат — эталонный, шесть колонок через TAB:

```
wylie <TAB> unicode <TAB> warns_w2u <TAB> wylie_back <TAB> warns_u2w <TAB> roundtrip_differs
```

- `wylie`, `unicode` — пара W→U: вход и ожидаемый тибетский текст;
- `warns_w2u` — ожидание по предупреждениям: `0` нет, `1` только в строгом
  режиме, `2` в обычном;
- `wylie_back`, `warns_u2w` — ожидания обратного хода U→W;
- `roundtrip_differs` — `0` означает «эталон тут же возвращается к тому же
  Юникоду», ненулевое — «не возвращается».

**Правило отсутствующих полей.** Эталон не везде задаёт всё: `ewts-rs` даёт
только пару W→U, `kang.txt` не задаёт ничего. Поэтому хвост строки может
обрываться, а в колонках ожиданий может стоять `?`. И то и другое означает
**«эталон не задаёт, проверять нечего»** — и никогда «ноль».

### Что проверяется

| Проверка | Что делаем | Обязательное поле |
|---|---|---|
| `w2u` | наш Wylie → Unicode против `unicode` | `wylie`, `unicode` |
| `u2w` | наш Unicode → Wylie против `wylie_back` | `wylie_back` |
| `roundtrip` | наш W→U→W→U обязан вернуть `unicode` (или отличаться, если `roundtrip_differs`) | `roundtrip_differs` |

**Про предупреждения.** Парит только конверсия: колонки `warns_w2u`/`warns_u2w`
парсер пропускает, проверок по ним нет и в baseline строк нет. Диагностика, её
коды и формулировки — наши (`Convert.Diagnostic`), свои ожидания лежат в
`Test.Diagnostic`; эталон как оракул предупреждений не используется (решение
30.09.2026).

**Что в диагностиках есть.** Канал наполняют и токенизатор, и грамматика:
неожиданный символ, незакрытая скобка, битый escape, окна легальности
(префикс, надстрочные, второй суперфикс, хвост слога, неоднозначность
написания) и токенизаторные случаи 3.4.6 — финал в начале прогона, точка без
стека. После Волны 4 канал пополнился документным предупреждением «текст без
тибетских букв» (шаг 4.2), а схлопывание прогонов пробелов в один тсек (шаг
4.1) сделано в токенизаторе — это рендер, а не предупреждение.

### Особенности исходных файлов

- `kang.txt` начинается с BOM, который стоит **на отдельной строке**, поэтому
  реальных строк 254, а не 255. Тест пропускает эту строку.
- В `lingua_parity.tsv` одна строка имеет `\r` в конце.
- `kang.txt` проверяется на обратимость (U→W→U), как сам jsewts
  (`kangtest.js` сравнивает свой `toWylie`→`fromWylie` с исходником), и — со
  шага 5.0 — против `wkang.txt`: дословной выгрузки `toWylie(kang.txt)` того же
  референса. Сверка идёт после нормализации: убраны ASCII-пробелы (и `_` на
  Wylie-стороне — это запись того же пробела у эталона), `༎` развёрнуто в
  `།།`. `rekang.txt` (`fromWylie(wkang.txt)`) **не импортирован**: под этой же
  нормализацией он равен `kang.txt` — это вторая петля самопроверки эталона,
  дубль round-trip-проверки (Q-5.1, сирота).
- `java_ewts.tsv` — это 5 строк, а не «36 проверок»: в `ConversionTest.java`
  из 36 assertion'ов EWTS-парами являются только 8 (6 уникальных) — все в методе
  `textEwts()`; остальные assertion'ы — DTS/ALALC (вне приоритета), отдельные
  sloppy-тесты (Волна 6) и lenient (вне приоритета). Одна из шести уникальных пар
  (`mNyon … padma`) конвертируется одноаргументным `toUnicode`, то есть через
  sloppy-путь, и вынесена в `java_sloppy.tsv` (шаг 4.4, Q-5); строгих W→U-пар у
  java, стало быть, пять.

### Находка на старте Волны 1

Три оставшихся расхождения на Кангьюре — все про `ནག` (U+0F7E). Этот кодepoint
**двусмыслен**: в нашей таблице он числится финальным знаком (анусвара `M`),
а в тибетском тексте это «реверсивная нага» — самостоятельная буква. Эталоны
разбирают это по контексту (в W→U `M` даёт анусвару, а `ནག` внутри текста —
букву). Отдельная задача для Волны 5; здесь просто зафиксировано, чтобы
изменение не потерялось.

### Известные пробелы (зафиксированы, чтобы не искать заново)

- `\X` выводит символ как есть, а мы — как тибетскую букву: `de la \3 yod/`
  должно дать `3`, а мы даём ༣ (правило 10 ewts-rs). Пока не чиним: правильный
  вывод требует «символ как текст», а не токена.
- `’` и `‘` — алиасы а-чунга (дефект 7, шаг 5.1), а вот «другие нелатинские
  кавычки» (`“`, `»` и т.п.) проходят насквозь как чужой текст.
- Строка 214 корпуса Lingua (`mgas`) говорит «0 предупреждений», а текущий
  `Wylie.pm` выдаёт `Syllable should probably be "mags".`: вендоренный корпус
  Lingua слегка устарел относительно вендоренного модуля. На конверсию это не
  влияет, а сверки предупреждений больше нет (см. «Про предупреждения»).

## Harness паритета (`test/parity/`)

Файлы прогонщика `Test.Parity` — наши, а не эталонные, поэтому лежат отдельно от
`test/vectors/`.

**Храповик.** `parity_baseline.tsv` хранит, сколько проверок каждого вида
проходило на момент записи. Тест падает, если стало **хуже**, и требует ровно
того же `total` — так молчаливое усечение корпуса не пройдёт. Записанное число —
**пол**, а не цель и не потолок: превышение пола тест не отмечает, и не
записанный выигрыш следующая волна отдаёт молча, поэтому прогресс волн
выражается **поднятием** храповика (числа в baseline растут), а не удалением
примеров; осознанное ухудшение фиксируется здесь же строкой-примечанием.

**Отчёт.** `cabal test hewts-test` всегда перезаписывает `parity_report.txt`: по
корпусу и виду проверки строка вида `jsewts (210 cases)` /
`  w2u  24/210  (baseline 24)`, ниже — все расхождения с ожиданием и фактом. Это
и есть «весы»: смотреть сюда, выбирать, что чинить в следующей волне.

Файл не отслеживается в git: это артефакт прогона, он перезаписывается при
каждом `cabal test hewts-test` и лежит только для чтения глазами.
