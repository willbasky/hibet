# Эталонные векторы (parity)

Здесь лежат проверочные примеры, скопированные из референсов, и раскладка
baseline'а, по которому `Test.Parity` следит за паритетом. Ничего из этого не
участвует в сборке библиотеки — файлы читает только тест-суит.

## Состав и происхождение

| Файл | Что это | Откуда | Ревизия |
|---|---|---|---|
| `jsewts_parity.tsv` | 210 случаев, W→U и U→W | `jsewts/test/test.txt` | jsewts `a3c8c6b` (2025-09-05) |
| `lingua_parity.tsv` | 218 случаев, тот же формат | `Lingua-BO-Wylie/t/test.txt` | без git-истории в нашей копии |
| `kang.txt` | 254 строки тибетского текста, без ожиданий | `jsewts/test/kang.txt` | jsewts `a3c8c6b` |
| `ewts_rs_rules.tsv` | 16 правил EWTS, только W→U | `ewts-rs/ewts/src/rules_test.rs` | ewts-rs `14f7b24` (2024-12-11) |
| `java_ewts.tsv` | 6 строк, EWTS-пары | `ewts-converter/.../ConversionTest.java`, метод `textEwts()` | ewts-converter `c1a6d3f` (2024-07-01) |
| `jsewts_warns.tsv` | тексты предупреждений, обычный режим | прогон самого jsewts по корпусу | jsewts `a3c8c6b` |
| `jsewts_warns_strict.tsv` | то же в строгом режиме | там же | jsewts `a3c8c6b` |
| `lingua_warns.tsv` | тексты предупреждений, `check_strict => 0` | прогон самого `Wylie.pm` по корпусу | без git-истории |
| `lingua_warns_strict.tsv` | то же при `check_strict => 1` | там же | без git-истории |
| `parity_baseline.tsv` | храповик: минимум проходящих проверок | наш файл | — |
| `parity_report.txt` | текущий полный список расхождений | генерируется тестом, в git не входит | — |

Первые три файла — **дословные копии**. Два вектора правил (`ewts_rs_rules.tsv`,
`java_ewts.tsv`) **извлечены** из исходников референсов, потому что там данные
лежат парами в коде, а не в таблицах. Файлы `*_warns*.tsv` — **разовый выгруз**
текстов предупреждений из самих эталонов: корпус хранит только их *число*, а
для паритета по тексту нужны сами строки.

Формат выгрузки: `caseLine` (та же нумерация, что в отчёте), затем тексты через
таб. Строка без текстов означает «в этом режиме предупреждений нет». Выгруз
сделан в двух режимах, потому что колонка `warns` различает 0 (нет), 1 (только
в строгом) и 2 (в обычном):

- jsewts: `{ check: true, check_strict: false, sloppy: true }` и то же с
  `check_strict: true` (как в `jsewts/test/wylie.test.js`);
- Lingua: `check_strict => 0` и `check_strict => 1` (как в `t/make-tests.pl`).

Сверка выгрузки с корпусом: у jsewts расхождений **ноль** — колонка `warns`
воспроизводится один в один. У Lingua одно расхождение из 218: строка 214
(`mgas`) в корпусе говорит «0 предупреждений», а текущий `Wylie.pm` выдаёт
`Syllable should probably be "mags".` — вендоренный корпус Lingua слегка устарел
относительно вендоренного модуля. Сверяемся с выгрузкой (поведение модуля
сегодня), а не с этой строкой корпуса.

## Формат

Формат — эталонный, шесть колонок через TAB:

```
wylie <TAB> unicode <TAB> warns_w2u <TAB> wylie_back <TAB> warns_u2w <TAB> roundtrip_differs
```

- `wylie`, `unicode` — пара W→U: вход и ожидаемый тибетский текст;
- `warns_w2u` — ожидание по предупреждениям: `0` нет, `1` только в строгом
  режиме, `2` в обычном;
- `wylie_back`, `warns_u2w` — ожидания обратного хода U→W;
- `roundtrip_differs` — `0` означает «эталон тут же возвращается к тому же
  Юникоду», ненулевое — «не возвращается».

**Правило отсутствующих полей.** Эталон не везде задаёт всё: `ewts-rs` даёт
только пару W→U, `kang.txt` не задаёт ничего. Поэтому хвост строки может
обрываться, а в колонках ожиданий может стоять `?`. И то и другое означает
**«эталон не задаёт, проверять нечего»** — и никогда «ноль».

## Что проверяется

| Проверка | Что делаем | Обязательное поле |
|---|---|---|
| `w2u` | наш Wylie → Unicode против `unicode` | `wylie`, `unicode` |
| `u2w` | наш Unicode → Wylie против `wylie_back` | `wylie_back` |
| `roundtrip` | наш W→U→W→U обязан вернуть `unicode` (или отличаться, если `roundtrip_differs`) | `roundtrip_differs` |
| `w2u-warnings` | наши тексты предупреждений против выгруженных текстов эталона | `warns_w2u` + файл `*_warns.tsv` |
| `u2w-warnings` | предуждаем ли мы вообще на обратном ходу | `warns_u2w` |

**Про тексты предупреждений.** Сравниваем с **нестрогим** режимом эталона: его
«только строгие» предупреждения (колонка `warns` = 1) относятся к режимам, а
режимы появятся в Волне 6. Обратное направление сверяется только по наличию
предупреждения — свои тексты для U→W мы не выгружали, и в корпусе их нет.

**Чего в диагностиках пока нет.** Канал (`Convert.Diagnostic`) существует, но
наполняет его только токенизатор: «неожиданный символ», незакрытая скобка,
битый escape. Слоговые предупреждения («Subjoined y not expected after r»,
«Invalid prefix consonant», «Cannot have more than one ^») и «No Tibetan
characters found!» — это Волны 3 и 4; сейчас они и составляют почти весь
остаток расхождений по `w2u-warnings`.

## Храповик

`parity_baseline.tsv` хранит, сколько проверок каждого вида проходило на момент
записи. Тест падает, если стало **хуже**, и требует ровно того же `total` — так
молчаливое усечение корпуса не пройдёт. Прогресс волн 2–6 выражается понижением
чисел в baseline, а не удалением примеров.

## Отчёт

`cabal test hewts-test` всегда перезаписывает `parity_report.txt`: по корпусу и
виду проверки строка вида `jsewts (210 cases)` / `  w2u  24/210  (baseline 24)`,
ниже — все расхождения с ожиданием и фактом. Это и есть «весы»: смотреть
сюда, выбирать, что чинить в следующей волне.

Файл не отслеживается в git: это артефакт прогона, он перезаписывается при
каждом `cabal test hewts-test` и лежит только для чтения глазами.

## Особенности исходных файлов

- `kang.txt` начинается с BOM, который стоит **на отдельной строке**, поэтому
  реальных строк 254, а не 255. Тест пропускает эту строку.
- В `lingua_parity.tsv` одна строка имеет `\r` в конце.
- `kang.txt` проверяется на обратимость (U→W→U), а не против ожиданий: так его
  проверяет сам jsewts (`kangtest.js` сравнивает свой `toWylie`→`fromWylie` с
  исходником). Сравнение идёт после нормализации эталона: убраны ASCII-пробелы,
  `༎` развёрнуто в `།།`.
- `java_ewts.tsv` — это 6 строк, а не «36 проверок»: в `ConversionTest.java`
  из 36 assertion'ов EWTS-парами являются только 8 (6 уникальных), остальное —
  DTS/ALALC (вне приоритета), sloppy (Волна 6) и lenient (вне приоритета).

## Находка на старте Волны 1

Три оставшихся расхождения на Кангьюре — все про `ནག` (U+0F7E). Этот кодepoint
**двусмыслен**: в нашей таблице он числится финальным знаком (анусвара `M`),
а в тибетском тексте это «реверсивная нага» — самостоятельная буква. Эталоны
разбирают это по контексту (в W→U `M` даёт анусвару, а `ནག` внутри текста —
букву). Отдельная задача для Волны 5; здесь просто зафиксировано, чтобы
изменение не потерялось.

## Известные пробелы (зафиксированы, чтобы не искать заново)

- `\X` выводит символ как есть, а мы — как тибетскую букву: `de la \3 yod/`
  должно дать `3`, а мы даём ༣ (правило 10 ewts-rs). Пока не чиним: правильный
  вывод требует «символ как текст», а не токена.
- `’` и другие нелатинские кавычки проходят насквозь, хотя эталон в части
  случаев ждёт от них а-чен (строка 5 java-вектора: `be’u'i'o`).
- Строка 214 корпуса Lingua (`mgas`) не сходится по предупреждениям с текущим
  `Wylie.pm` — см. раздел о выгрузке выше.
